# **Project Roadmap**

### **1. Эпики и спринты.**
*1 спринт проходит примерно 2 недели.*

| Спринт       | Эпик                                            | Цель                                                      | Ключевые задачи                                                                                                                                                                                 | 
| :----------- | :---------------------------------------------- | :-------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | 
| **Спринт 1** | **Базовая инфраструктура и управление данными** | Подготовить основу приложения и базу данных               | <ul><li>Настройка окружения (Docker, Git, CI/CD)</li><li>Создание моделей данных: Vacancy, Candidate</li><li>Загрузка и хранение резюме</li><li>Парсинг текстов (PDF, DOCX)</li></ul>                    |
| **Спринт 2** | **AI-анализ и скоринг кандидатов**              | Реализовать базовую функциональность анализа соответствия | <ul><li>Интеграция LLM API (OpenAI/Anthropic)</li><li>Выделение ключевых навыков и опыта</li><li>Расчёт скоринга по формуле вес × совпадение</li><li>Отображение рейтинга кандидатов</li></ul> |   
| **Спринт 3** | **Генерация вопросов и UX улучшения**           | Создать AI-интервью функциональность                      | <ul><li>Интерфейс выбора кандидатов</li><li>Генерация вопросов и кейсов LLM</li><li>Редактирование и утверждение вопросов</li><li>UX: визуализация процесса анализа</li></ul>                      |  
| **Спринт 4** | **Экспорт, интеграции и оптимизация**           | Завершение MVP, добавление интеграций                     | <ul><li>Экспорт результатов в PDF</li><li>Интеграция с HRM API (опционально)</li><li>Логирование и безопасность</li><li>Оптимизация запросов, кэширование</li></ul>                                |  
### **2. Зависимости задач**
Без реализованного парсинга резюме невозможно запустить анализ.

Без анализа не будет данных для генерации интервью-вопросов.

Без генерации нельзя сформировать финальный отчёт (PDF).

### **3. Приоритизация MVP (Minimum Viable Product) функций**
1. Загрузка данных	- Загрузка вакансий и резюме (PDF, DOCX)	
2. AI-анализ -	Выделение навыков и сравнение с требованиями	
3. Скоринг -	Автоматический расчёт соответствия	
4. Интерфейс -	Отображение рейтинга и базового списка кандидатов	
5. UX -	Простая панель управления и статус обработки

### **4. Планирование рисков и их митигация**

| Риск                                       | Митигация (снижение последствий)                   |
| -----------------------------------------  | -------------------------------------------------- |
| Перегрузка LLM API / лимиты запросов    | Кэширование результатов, очередь задач Celery      |
| Ошибки при парсинге резюме              | Использование fallback-парсера (pdfplumber + docx) |
| Низкое качество анализа (ошибки LLM)    | Настройка prompt'ов, валидация данных вручную      |
| Потеря данных при сбое сервера          | Регулярное автосохранение и резервное копирование  |
| Конфиденциальность персональных данных  | Обезличивание данных при передаче в LLM            |
